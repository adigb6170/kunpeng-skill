# UI 与交互蒸馏

## 目标

提取界面的任务组织、布局、状态和反馈规律，使结果能指导新产品，而不是只复述页面长相。

## 页面骨架

逐页识别：

- 全局导航、局部导航和返回路径。
- 顶栏、侧栏、工具栏、底栏和浮动操作区。
- 主工作区、详情区、预览区、属性区和辅助面板。
- 列表、表格、卡片、表单、日志、时间线和内容阅读区。
- 弹窗、抽屉、菜单、提示、确认和批量操作。
- 3D、Canvas、地图、编辑器、图表、游戏场景和 HUD 的位置及尺寸约束。

先判断主任务占据哪里、次要信息如何收起，再评价视觉形式。

## 任务与导航

1. 写清用户进入、定位目标、执行操作、确认结果和返回的完整路径。
2. 判断主要命令是否在需要它的上下文附近，而不是散落在页面。
3. 检查深层页面是否保留方向感、状态和返回位置。
4. 区分浏览型、创作型、监控型、交易型和游戏型界面，不套用同一种信息密度。

## 状态清单

关键功能至少检查：

- 初始、加载、空、部分完成、成功、失败、离线和权限不足。
- 默认、悬停、聚焦、按下、选中、禁用和处理中。
- 保存、撤销、重做、确认、取消和离开未保存内容。
- 长任务进度、可恢复性、日志、通知和错误修复入口。

素材没有展示某状态时标记为缺口，不替项目补写成事实。

## 动效判断

每个动效回答五件事：

1. 在什么触发下发生？
2. 帮助理解层级、连续性、反馈还是品牌表达？
3. 出现频率多高？高频操作必须更克制。
4. 时长、缓动、延迟、位移、缩放和交错量如何？无法测量时给区间并标明建议。
5. 低性能、减少动态效果和触控环境下如何降级？

删除没有目的、拖慢任务或反复打断注意力的动画建议。

## 特殊界面

### 3D、Canvas 与地图

说明它是主工作区、背景、预览还是数据层。检查镜头、缩放、旋转、选择、命中区、加载、空白画布、设备性能和普通 DOM 控件的关系。3D 不得只作为与业务无关的装饰。

### 编辑器与创作工具

检查素材入口、画布、图层、属性、历史、导出和快捷操作的空间关系。保持工具尺寸稳定，避免动态标签造成布局跳动。

### 游戏

围绕核心循环分析 HUD、输入反馈、关卡状态、暂停、教程、失败、奖励和重玩。区分游戏世界信息与系统菜单，不让提示遮挡关键操作。

## 响应式与可访问性

- 检查桌面、窄屏和触控布局的结构变化，不只检查缩放。
- 保证文本不溢出、不遮挡，固定格式区域使用稳定尺寸和响应式约束。
- 检查键盘焦点、语义标签、对比度、触控目标和减少动画偏好。
- 不用颜色作为唯一状态信号。

## 输出规则

输出布局、导航、关键任务、组件配合、状态、反馈、响应式和视觉节奏。产品规划中写成目标产品自己的 UX 蓝图，不列资料来源或参考项目。
