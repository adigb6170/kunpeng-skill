# 方法论蒸馏

## 目标

把项目、书籍、课程、视频、访谈、图片或混合素材中的知识转成可触发、可执行、有边界的规则，并形成可再生成、可验证的规范。不要把摘要、金句、风格形容词或常识包装成方法论。

纯蒸馏直接处理素材，不进行产品需求问答。只有用户要求据此规划或开发新产品时，才进入 `product-discovery.md`。

## 全局理解

在局部提取前先回答：

- 来源试图解决什么问题？
- 核心命题和论证链是什么？
- 哪些是已实现事实，哪些是主张或路线图？
- 哪些案例支持或反驳主要观点？
- 哪些限制会改变结论？

长内容按章节、课程单元、场景或时间段切分，并让每个分块携带同一份全局概览。

## 五类提取

1. **框架**：组织问题的结构和步骤。
2. **原则**：反复影响决策的规则。
3. **案例**：方法有效时的具体表现。
4. **反例**：失败、误用和边界条件。
5. **术语**：对理解方法必要且有特殊含义的概念。

有并行能力时可分别提取；没有时串行执行。合并前保持各视角独立，避免一种解释吞掉其他证据。

## 候选筛选

候选规律必须满足：

1. **支持度**：有真实代码、页面、画面、案例或多处材料支持。
2. **迁移性**：能用于新的问题，而不是只描述原对象。
3. **独特性**：不是“保持简洁”“关注用户”等通用常识。
4. **行动性**：能指导选择、步骤、参数或检查。
5. **边界性**：能说明何时不用、代价是什么、失败会怎样。

不足项降级为观察或淘汰，不为凑数量保留。

## 方法卡

```text
触发场景：什么时候需要这项方法
核心判断：它改变了什么决策
执行步骤：按什么顺序操作
参数与检查：怎样判断做到了
反例：常见错误或诱饵
边界与代价：什么时候不适用
```

原始证据和来源映射只在内部研究或资料库索引中保留。面向产品规划的最终内容去掉来源名称，保留经过验证的规则和边界。

## 再生成转化

对视频、图片和文章，方法卡还要转换为：

```text
目标模式 → 不可变项 → 内容变量 → 生成顺序 → 参数化规则 → 负向约束 → 验收条件
```

这份规范是蒸馏结果本身，不另写一段脱离证据的“万能提示词”。需要投喂具体生成工具时，再按 `reproduction-standard.md` 映射格式。

## 矛盾处理

- 先检查是否来自不同用户、阶段、平台或成本条件。
- 能按条件分开的，写成条件化规则。
- 无法解释的矛盾继续保留，不选择更顺耳的一边。
- 时间敏感的技术结论标记有效期，并在使用前重新核对官方资料。

## 测试

为高价值方法准备：

- 正例：明显应该使用。
- 诱饵：表面相似但不应使用。
- 边界：信息不足或代价过高。
- 冲突：与相邻方法给出不同选择。
- 迁移：换行业、平台或用户后仍能产生有效判断。

优先让未看到预期答案的独立 Agent 评估；无法独立评估时按测试清单自查并降低确定性。

## 批量蒸馏

先逐项建事实卡，再聚类、去重和统计频率。输出共同规律、重要分歧、少数高价值例外和不适用条件，不生成逐项摘要堆积。批量风格规范必须区分系列固定规则、内容变量和异常样本。
