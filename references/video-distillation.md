# 视频蒸馏

## 直接执行

纯视频蒸馏不做产品需求问答。先确认素材可读取、用户要求是“忠实重建”还是“同风格新内容”；未说明时按同风格新内容处理，并把原内容当作分析证据而非可复制资产。

运行前读取 `local-toolchain.md`，先执行：

```bash
python scripts/kunpeng.py probe --profile video
```

普通蒸馏不得加 `--strict`；缺少某个组件时继续执行其余阶段。完整安装验收才使用 `probe --profile all --strict`。

标准处理：

```bash
python scripts/kunpeng.py video <视频或目录> --output <过程目录>
```

默认使用第一条音轨。`auto` 会保留已有字幕，并在 faster-whisper 可用时同时运行 ASR 交叉核对；主文本优先字幕。多语言或多音轨素材先从 `probe.json` 找到音轨索引，再用 `--audio-stream <索引>`；明确要求双轨完整时使用 `--transcript-source both`。

完全离线或已有本地模型时：

```bash
python scripts/kunpeng.py video <视频或目录> --output <过程目录> --whisper-model <本地模型目录> --offline
```

## 过程文件

先读 `manifest.json`，再按需读取每个视频的 `analysis.json`。不要把整个过程目录一次放入上下文。

- `probe.json`：时长、分辨率、帧率、音轨和字幕流。
- `subtitles/`：可转换的原生字幕和同名外挂字幕副本。
- `transcript.json` / `transcript.txt`：带时间戳的主转写和可用轨道。
- `scenes.json`：镜头边界；固定间隔降级会明确标注。
- `keyframes/`：镜头中点关键帧、索引和联系表。
- `ocr.json`：按时间取样的画面文字及去重区间。
- `audio-analysis.json`：节拍估计、响度、停顿、频谱和时间包络。
- `timeline.json`：镜头、讲话与画面文字合并后的事件流。

## 分析顺序

1. 用 `analysis.json` 确认哪些阶段真实完成；按 `complete`、`degraded`、`partial`、`failed`、`not_applicable` 解释，不把已准备但尚未执行的宿主复核算作覆盖。
2. 先完成 `host_review_required` 中列出的真实关键帧、联系表或音频检查，再判断缺口是已降级覆盖还是仍为部分完成。
3. 通读主转写，建立主题、叙事段落、人物/物体、动作和情绪变化。
4. 读 `scenes.json` 和关键帧联系表，按开场、发展、转折、高潮、收束建立完整镜头结构。
5. 对重要镜头查看原始关键帧，记录景别、机位、镜头运动、主体运动、构图、光线、色彩、材质、特效和转场。
6. 把音频节拍、停顿、讲话和剪辑点对齐，判断声音如何驱动画面，不把 BPM 估计直接等同于音乐风格。
7. 检查 OCR 与字幕差异，区分旁白、对白、标题、界面文字和烧录字幕。
8. 批量视频先逐个形成事实卡，再统计共同规律、分支、例外和不同内容条件。

## 最终产物

最终蒸馏文档至少包含：

- 视频定位、受众、观看场景和核心效果。
- 叙事结构与时长占比。
- 镜头语法、构图、镜头运动、主体运动和转场规则。
- 色彩、光线、材质、字幕/图形和特效系统。
- 旁白/对白、声音层次、节奏、停顿与画面对齐方式。
- 可复用规则、内容变量、禁止项、失败模式和适用边界。
- 按 `reproduction-standard.md` 形成可再生成规范与验收表。

忠实重建必须给出逐镜时间表；同风格新内容可用归一化时长比例，但仍要说明各段的镜头数量、节奏和连接方式。

## 完整性门

- 时间轴是否覆盖从第一帧到最后一帧，没有只分析高光片段？
- 转写来自字幕还是 ASR 是否明确，未听清位置是否保留？
- 是否检查了画面文字、声音和剪辑的同步关系？
- 是否区分稳定风格与单个内容造成的偶然镜头？
- 规范是否足以让另一个生成系统重建时长、镜头、动作、声音和连续性？
- 是否避免承诺逐帧完全一致，并要求对生成结果重新取样复核？
